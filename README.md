# PaperPass AIGC 降重实战手册

> 一篇 3000 字的工科课程论文，在 PaperPass 上从 **58.31% 降到 17.08%**，用了 13 个版本。
> 这里记录每一步做了什么、哪一步有用、哪一步是坑。
>
> **核心结论：决定分数的不是「改了多少字」，而是「改成了什么语体」。**

---

## 一、实测数据

同一篇论文（《基于机器视觉的注塑件表面缺陷检测方法研究》，3000 字，15 篇文献，4 张图），同一账号，连续送检。

| 版本 | 做了什么 | AIGC | 重复率 | 结果 |
|---|---|---|---|---|
| v2 | 口语化改写 | 47.24% | 2% | — |
| v3 | 全部改成规范学术语 | 58.31% | 4% | ❌ 越规范越高 |
| v4 | v3 + 10 段口语化 | 40.85% | 3% | 有改善 |
| v6 | v4 + 8 段换词改写（修改率 15%） | 41.00% | — | ❌ 完全没动 |
| v9 | 全篇「结构重写」，改得更正式 | **60.27%** | — | ❌ 暴涨 |
| v11 | 全篇口语化 + 5 段调试细节 | 34.40% | — | 大幅下降 |
| v12 | v11 + 20 个短段合并成 8 个长段 | 32.69% | — | 小幅下降 |
| v13 | **只改 7 段被标色的，改成「平实正式」** | **17.08%** | 3% | ✅ 达标 |

**从 60.27% 到 17.08%，只用了两步：把段落合并，再把被标色的段落从「精致」改成「平实」。**

## 二、五条核心发现

### 1. 「正式」和「精致」是两件事

这是最大的坑。我一开始把「降低 AI 味」理解成「写得更规范、更学术」，结果 v3 和 v9 都暴涨到 58%~60%。

真正涨分的是**「精致」**，不是「正式」：

```
❌ 精致（涨分）：镜头与相机的选择需以检测精度为起点反向推导
                推理阶段另实施了半精度量化
✅ 平实（降分）：选型从检测精度倒推
                推理端做了半精度量化，模型从 27 MB 降到 14 MB
```

「以…为起点反向推导」「实施」「另」——这些是期刊腔的标志，也是语言模型最容易预测的词序列。

**「平实正式」和「口语」都能降分，但平实的副作用小得多。**

### 2. 只改被标色的段落，整篇重写会翻车

v9 我全篇重写了 30 段，修改率 32%，结果从 41% 涨到 60.27%。

原因：**改写本身会引入新的 AI 指纹**。`xiaofenggan01/aigc-reduce` 里明确写了这一条——用 AI 重写 AI 文本，检测率可能升到 100%。

正确做法：报告里**没被标色的段落，一个字都不要动**。

### 3. 修改率低于 20% 等于没改

v4 → v6 改了 8 段，字符级修改率 15%，AIGC 从 40.85% 变成 41.00%。

用 `scripts/check_mod.py` 量一下就知道：

```
<20%    基本无效
20-40%  有效但不强
>40%    大幅变化（但注意发现 2：整篇重写会翻车）
```

**改得够多 ≠ 改得对。** 关键是改的位置和方式。

### 4. 段落长度有硬阈值

v11 的报告里，20 个被标色的段落和 20 个通过的段落，按字数排开：

```
通过：  108、113、125、127、133、134、137、138、143、145、155、158、166…
标色：   53、 53、 60、 63、 63、 66、 67、 67、 68、 70、 84、 91、 94、 99、101、123
```

**分界线在 110 字左右。短于这个长度的段落，基本全灭。**

把 20 个短段合并成 8 个长段（内容一字未改），分数从 34.40% 降到 32.69%。

### 5. 具体细节比句式更能拉低分数

v11 里加了 5 段真实调试细节：

- 环形光装在镜头正前方拍不出缩痕，换 45° 低角度才成
- 相机支架螺丝松了半圈，边缘的件全被判成飞边
- 缩痕试了正打、侧打、背打三种光
- 第一轮学习率 0.1，验证集准确率停在 16.7%（六个类别，等于瞎猜）
- 标注分歧：关掉一路光再看，还在的算缺陷

**这些内容不在任何训练语料里，模型无法预测，困惑度天然高。**

## 三、标准工作流

```
1. 送检，下载「Word 标红版 AIGC 检测报告」
        ↓
2. python3 scripts/parse_report.py 报告.docx
   → 看颜色分布、被标色段平均字数 vs 通过段平均字数
        ↓
3. 若「被标色段」明显更短 → 先做段落合并（prompts/03）
   合并后再送检一次，看是否有效
        ↓
4. 只把红/橙/紫的段落贴给模型，用 prompts/01（平实正式版）
   一次一段或两三段，其余段落一个字不动
        ↓
5. 重新送检
        ↓
6. 仍 >30% → 用 prompts/02（口语化版）兜底
   目标 ≤30% 即可，不要追求更低
```

**通常 2~3 轮收敛。每轮只改被标色的部分。**

## 五、快速开始

```bash
pip install python-docx

# 1. 看报告哪里红
python3 scripts/parse_report.py 报告.docx --only-flag

# 2. 改完对比修改率
python3 scripts/check_mod.py 旧版.docx 新版.docx
```

然后把 `prompts/01-平实正式版.md` 的内容连同**被标色的段落**一起贴给任意大模型。

## 六、不要做的事

| ❌ 不要 | 为什么 |
|---|---|
| 整篇重写 | v9 实测涨到 60.27% |
| 改成更精致、更学术的表达 | v3/v9 实测涨分 |
| 只换同义词 | v6 实测完全无效（41% → 41%） |
| 追求 0% | 30% 是门槛，不是越低越光荣；过度口语化会毁掉文风 |
| 改摘要和结论的口语化 | 老师必看，掉印象分 |
| 为了凑修改率加废话 | 会被检测器和老师同时识破 |

## 七、原理（简短版）

主流 AIGC 检测器看两件事：

- **困惑度（Perplexity）**：给定前文，下一个词有多难猜。AI 写作总是选概率最高的词，困惑度低。
- **突发性（Burstiness）**：句长变化幅度。AI 的句子长度集中在 20~35 字，人类是长长短长短。

PaperPass 官方说法是「AI 对战 AI」，用模型判断文本的「风格指纹」。

**所以有效的改写方向是：让词的选择变得不那么可预测，让句长变得不规律。** 口语化和「平实」都做到了这一点；「精致学术腔」恰好相反。

## 第二次实战（2026-10-29）：提示词的上限在哪

同一套提示词换一篇论文，**71% 只降到 44.7%**。

```
初稿（AI 生成，标准总—分—总结构）        71%
用户自己改写（拆长句 + 加口语）            44.7%
按标红段落逐段重写（具体化 + 换骨架）      待测
```

**关键发现：**

1. 标红报告里 **13 个段落是 100% 标色**，摘要 290 字全红——不是零星几个词的问题
2. 提示词改的是「语体」，检测器看的是「统计特征」（困惑度、句长分布、信息密度均匀度），语体变了指纹没变
3. 用户第一次改法是「拆长句 + 加口语」，但每段骨架还是「总起—分述—收尾」，13 段同一个骨架 = 新模板
4. 真正有效的是**注入具体数字/场景 + 换段落骨架 + 句长突变**

**边界：** 这套方法对 AIGC 检测有效，对**查重（文字复制比）几乎无效**——查重看的是与库中文献的连续 13 字重合，两套机制要分开处理。

详见 [docs/2026-10-29-第二次实战.md](docs/2026-10-29-第二次实战.md)。
