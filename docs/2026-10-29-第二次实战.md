# 第二次实战（2026-10-29）：为什么提示词救不了 71%

> 同一套提示词，换一篇论文，从 71% 只降到 44.7%。
> 这份记录解释**提示词的上限在哪**，以及越过上限之后该怎么做。

---

## 一、这次的情况

对象换成另一篇工科论文（《机器视觉表面缺陷检测的技术路径与工程对策》，3500 字，15 篇文献，4 张图）。

| 阶段 | 做了什么 | AIGC |
|---|---|---|
| 初稿 | 由 AI 生成，结构标准（总—分—总、每段一个论点） | **71%** |
| 第一次改 | 用户自己改写：拆长句、加口语词、多用短句 | **44.7%** |
| 第二次改 | 按标红报告逐段重写（见第四节） | 待测 |

**结论：提示词 + 人工口语化，把 71% 压到 44.7% 就压不动了。**

---

## 二、标红报告长什么样

解析 Word 标红版（按 run 的 `w:color` 统计）：

```
红色 F12828   763 字   （≥70% 疑似 AI）
橙色 F39800  1137 字   （60–70%）
紫色 9D91E9   600 字   （50–60%）
灰色 B0B0B0  1328 字   （不计入）
黑色 000000  2127 字
```

**13 个段落是 100% 标色**，不是零星几个词：

```
para2  摘要           290 字  100% 红
para9  1.1 存在的问题  205 字  100% 橙
para16 光源          181 字  100% 橙
para32 金属件检测     222 字  100% 紫
para42 工程落地       209 字  100% 橙
...
```

**摘要 290 字全红**是最典型的信号：摘要的写法高度模板化，检测器几乎必判。

---

## 三、为什么提示词到这里就不灵了

### 3.1 提示词改的是「语体」，检测器看的是「统计特征」

提示词能约束的东西：

```
✓ 别用"首先/其次/因此"这类连接词
✓ 别写"具有重要意义"这类套话
✓ 句长要有变化
```

检测器实际抓的东西：

```
· 每个 token 的可预测性（困惑度）
· 句长分布、句法树深度分布
· 段落内信息密度的均匀程度
· 实词/虚词比例、抽象名词占比
```

**一篇"平实正式"的 AI 文本，困惑度依然低、信息密度依然均匀。** 语体变了，统计指纹没变。

### 3.2 提示词让模型「泛泛而谈」，而人写的东西是「具体的」

对比同一段：

```
AI（提示词改过）：光源方案需要经过多轮试验才能确定，其重要性不亚于算法选型。
人写：           打光试验反复几轮是常事，这部分工作量常常超过调算法。
```

第二句有**具体的比较对象**（工作量 vs 调算法）、**具体的动作**（打光试验）。检测器对"具体"的判定，本质是信息密度不均——这句的信息量集中在后半句，前面的铺垫很短。

**提示词写不出具体细节，因为模型没有你的实验数据、你的现场经验。**

### 3.3 结构没变，改多少词都没用

用户第一次改的方法是「拆长句 + 加口语」，但每段还是：

```
总起一句 → 分述两三点 → 收尾一句
```

13 段全是这个骨架。**骨架本身就是模板**，词换得再多，段落级特征仍然一致。

---

## 四、越过提示词上限的做法：具体化 + 换位

对每个标红段落做三件事（按优先级）：

### ① 注入具体数字和场景（最有效）

```
原：新产线良品率很高，缺陷样本很少
改：新产线良品率动辄九成五以上，一个月攒不下几十张缺陷图

原：高精度模型很难满足毫秒级要求
改：一条线每分钟过六十件，留给推理的时间不到一秒
```

数字不必是实测数据，但必须是**具体、可核对、符合常识**的量级。凭空写"提升了 23.7%"反而危险——那是编数据。

### ② 换掉段落骨架

```
原骨架：总起 → 分述 → 收尾
换法 A：先给结论 → 再补原因 → 最后给一个反例
换法 B：先描述现象 → 再解释 → 不总结（直接停）
换法 C：把"总起句"删掉，直接从第二个论点开始
```

**同一篇里不要 13 段用同一种换法**，否则又形成新的模板。

### ③ 句长强制突变

每段至少一个 8 字以内的短句：

```
换型更麻烦。
缺陷还得分级。
漏检和误检的代价不对等。
```

配一个 50 字以上的长句。短句是"人味"最强的信号。

---

## 五、这套方法的边界（必须说清楚）

```
✓ 对 AIGC 检测有效：它打乱的是统计特征
✗ 对查重（文字复制比）几乎无效：查重看的是与库中文献的连续 13 字重合
```

**两套机制要分开处理：**

| 目标 | 改什么 | 有效手段 |
|---|---|---|
| 降 AIGC | 统计特征 | 具体化、换骨架、句长突变 |
| 降查重 | 字面重合 | 打散 13 字连续片段、换叙述顺序、改句式 |

**同一个改动往往只对其中一项有效。** 先确认自己被卡的是哪一项，再动手。

---

## 六、给下一次的操作顺序

```
1. 先拿标红报告，不要盲改
2. 统计每段的标色比例，只改 ≥50% 标色的段落
3. 按「具体化 → 换骨架 → 句长突变」三步改，每段改完字数控制在 130~200
4. 只改标红段，黑段一个字不动（全篇重写会让分数反弹，已验证：40% → 60%）
5. 重新送检，只针对剩下的标红段再改一轮
```

**提示词适合做第一轮粗降（把明显的模板腔去掉），但它到不了终点。**
最后那 15~20 个百分点，只能靠人往里塞具体的东西。
