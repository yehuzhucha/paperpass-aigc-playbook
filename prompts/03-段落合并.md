# 提示词 C：段落合并（结构性调整，实测 34.40% → 32.69%）

> 用途：报告显示「被标色的段落明显比通过的段落短」时用。
> 实测：同一篇论文里，短于 110 字的段落**几乎全部**被标色，长于 130 字的段落**几乎全部**通过。

---

## 判断依据

先跑 `scripts/parse_report.py`，看这两行：

```
被标色段平均 xx 字（min~max）
通过段平均   xx 字（min~max）
```

如果「被标色段」的平均字数明显更小（比如 70 字 vs 140 字），就说明该合并了。

**本项目的实测分界线：110 字。**

## 怎么合并

把相邻的 2~4 个短段合成一段，**内容一个字不改**，只做三件事：

1. 删掉中间多余的段首重复主语
2. 把句号改成逗号或分号（视语义而定）
3. 补一句过渡，把两段接上

### 例

改前（3 段，共 195 字，全部被标色）：

```
标定别省。棋盘格标一次管一个月；镜头松了、换了工装，必须重标。

多机同步靠触发板发脉冲，软件时间戳只能补偿，这一环调试时最容易被跳过。

成本也值得说一句。相机镜头占一半，光源和结构件三成，算力只占剩下那点。
```

改后（1 段，285 字，通过）：

```
标定环节不能省。用棋盘格标定一次，有效期大约一个月；镜头一旦松动或者更换工装，
就必须重新标定。不重新标定的后果比较直接：畸变校正会把画面边缘的缺陷拉变形，
尺寸判定也跟着出错。多相机同步是另一个容易被跳过的环节：脉冲由触发板统一发出，
软件时间戳只用来做补偿。同步误差超过 5 ms 时，同一个制件的多视角图像就会错位，
拼接和复判都会受到影响。成本方面，相机和镜头大约占一半，光源和结构件占三成，
算力只占剩下的一部分。
```

## 注意

- **合并后段落不要超过 400 字**，太长读起来累，Word 排版也难看。
- 合并前先确认这几段是同一主题（同一节、同一逻辑层）。跨主题硬合会显得混乱。
- 合并本身不改内容，所以**不会改变查重率**，只影响 AIGC。

## 什么时候别用

- 论文本身段落就都很长（平均 200 字以上）——那问题不在长度
- 报告里被标色的段落和通过的段落长度差不多——说明长度不是主因
